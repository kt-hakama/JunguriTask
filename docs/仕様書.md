## 1. 概要

### 1.1 製品の位置づけ

本製品は **タスク管理ツールではない**。ユーザーが **順番に一つずつ** 作業を進め、完了した項目を末尾へ回す **連続フロー（シーケンシャルループ）** を支援する Web アプリである。

- 締切・優先度・評価を設けず、判断負荷を減らす。
- リストは上から順に処理し、完了したタスクは末尾へ移動し、**循環**する。

### 1.2 名称

- **表示名**: じゅんぐりタスク
- **リポジトリ名**: JunguriTask（参考）

### 1.3 技術スタック

| 区分 | 技術 |
|------|------|
| フロントエンド | React 18（Hooks） |
| ビルド | Vite |
| スタイル | Tailwind CSS |
| データ保存 | ブラウザ `localStorage` のみ（サーバー・バックエンドなし） |

### 1.4 対象環境

- **モバイルファースト** の画面設計。
- モダンブラウザ（`localStorage`・ES モジュールに対応した環境）。

---

## 2. スコープ外（実装しない機能）

以下は **意図的に含めない**。

- 締切・期限・リマインダー
- 優先度・タグ・メモ・ノート
- カレンダー連携
- タスクの **並べ替え（ドラッグ等による任意順序変更）**
- ユーザー認証・クラウド同期
- 複数端末間のデータ共有（サーバーがないため）

---

## 3. 画面構成と遷移

### 3.1 画面一覧

| 画面 | 名称 | 役割 |
|------|------|------|
| 画面1 | リスト選択 | リストの一覧・作成・削除・名前変更・リストを開く |
| 画面2 | タスク画面 | 選択した1リスト内のタスクの表示・操作 |

### 3.2 遷移

- **タブ・複雑な URL ルーティングは使用しない**（クライアント内の状態で画面を切り替え）。
- 画面2 から画面1 へは **戻る** 操作（ヘッダの戻る）で戻る。

### 3.3 リストの独立性

- リストは **最大 3 件**。
- 各リストは **完全に独立**（タスク・状態の共有なし）。

---

## 4. 画面1：リスト選択

### 4.1 表示

- アプリタイトル「じゅんぐりタスク」。
- 登録済みリストを **リスト名のみ** で一覧表示。
- リスト件数が 3 未満のとき、**リストを作成** 用の入力欄とボタンを表示。

### 4.2 操作

| 操作 | 仕様 |
|------|------|
| リストをタップ | 該当リストの **画面2** へ遷移 |
| リストを作成 | 入力が空のときは名前を「新しいリスト」として作成。最大 3 件を超えては作成しない |
| 名前を変更 | **鉛筆アイコン**（`aria-label`: 名前を変更）。インライン編集。保存／キャンセル。名前が空にした場合は **変更前の名前を維持** |
| 削除 | **ゴミ箱アイコン**（`aria-label`: リストを削除）。該当リストをデータから除去 |
| すべてのデータを削除 | 確認ダイアログの後、**全リスト・全タスク** を削除（初期状態に戻す） |

---

## 5. 画面2：タスク画面

### 5.1 ヘッダ

- **戻る**: 画面1へ戻る。
- リスト名を表示（長い場合は省略表示）。**リスト名をタップ**または **鉛筆アイコン**（`aria-label`: リスト名を編集）でインライン編集（保存／キャンセル）。空にして保存した場合は **変更前の名前を維持**（画面1の名前変更と同様）。

### 5.2 タスクが0件のとき（空リスト）

- 文言: 「最初のタスクを追加しましょう」。
- タスク名入力と **タスク追加** ボタン。

### 5.3 タスクが1件以上あるとき

#### 5.3.1 先頭タスク（次にやること）

- **大きく強調**したカードで表示。
- **完了** ボタンを表示。
- タスクが **2件以上** あるときのみ **スキップ** ボタンを表示。
- **タスク名をタップ**でも編集入力モードになる。メニュー（⋮）から **鉛筆アイコン**（名前を編集）および **ゴミ箱アイコン**（タスクを削除）（先頭タスクのみ）。編集中は完了・スキップは表示しない。

#### 5.3.2 2件目以降

- 見出し「このあと」。
- 各タスクを **小さめの行** で表示。**タスク名をタップ**または **鉛筆アイコン**（編集）で名前を変更（保存／キャンセル）。**ゴミ箱アイコン**（削除）から確認ダイアログ経由で削除可能。

#### 5.3.3 タスク追加（空でないとき）

- 画面下部に入力欄と **タスク追加**。
- 新規タスクは **常にリスト末尾** に追加。

#### 5.3.4 最終完了日の表示

- **`lastCompletedAt` が null** のときは **行ごと非表示**。
- 表示内容は **時計アイコン** ＋ **月/日（曜）** の短い形式（例: `4/5（日）`）。**年・時刻は出さない**。端末の **ローカルタイムゾーン** で解釈する。
- 意味は **`lastCompletedAt` に記録された最終「完了」時刻** に対応する日付であり、キュー上の位置とは無関係。**スキップでは `lastCompletedAt` を変えない**ため、スキップ後も過去に完了していれば表示は残る。
- **先頭カード**: タスク名の直下に1行（補助テキスト）。**完了・スキップ** ボタンより上に置き、主操作と競合しない。
- **このあと** の各行も **同じ1行ルール** で、タスク名行の直下に揃える。名前編集中は非表示（編集 UI のみ）。
- 完了直後のトースト等は **付けない**。詳細メニューも **付けない**。

## 6. タスクのデータ項目

| 項目 | 型 | 説明 |
|------|-----|------|
| id | 文字列 | 一意識別子（UUID または同等の一意性を持つ生成） |
| name | 文字列 | 表示名（前後空白は追加時に trim） |
| lastCompletedAt | 数値または null | 最終「完了」操作時の時刻（Unix エポックミリ秒・端末ローカルで表示に変換）。未完了扱いは null。UI では月/日（曜）と時計アイコンで示す（5.3.4） |

---

## 7. タスク操作の振る舞い（仕様の核心）

### 7.1 完了

1. **先頭タスク** を対象とする。
2. **2件以上** ある場合: 先頭を取り除き、**`lastCompletedAt` を現在時刻で更新したうえで末尾** に追加する（ループ）。
3. **1件のみ** の場合: 順序は変えず、当該タスクの **`lastCompletedAt` のみ** を現在時刻で更新する。

### 7.2 スキップ

- **2件以上** あるときのみ有効。
- 先頭を末尾へ移動するが、**`lastCompletedAt` は更新しない**。
- **1件のみ** のときはスキップは行わない（ボタンも表示しない）。

### 7.3 削除

- 指定 id のタスクをリストから除去。
- **先頭を削除** した場合、次のタスクが新たな「先頭」になる。

### 7.4 追加

- 常に **配列の末尾** に追加。`lastCompletedAt` は null。

### 7.5 名前の編集

- 指定 id のタスクの **`name` のみ** を更新する。`id`・`lastCompletedAt`・順序は変えない。
- 保存時に **前後空白は trim**。trim 後が **空文字** の場合は **変更前の名前を維持**（リスト名の名前変更と同様）。

## 8. 永続化

### 8.1 保存場所

- キー名: `junguri-task-data`
- 形式: JSON 文字列を `localStorage` に保存。

### 8.2 データ構造（論理）

```json
{
  "lists": [
    {
      "id": "文字列",
      "name": "文字列",
      "tasks": [
        {
          "id": "文字列",
          "name": "文字列",
          "lastCompletedAt": null
        }
      ]
    }
  ]
}
```

`lastCompletedAt` は完了後は数値（Unix エポックミリ秒）となる。

### 8.3 読み込み時の検証

- JSON 解析失敗時は **空の `lists`** にフォールバック。
- `lists` が配列でない等、構造が不正な場合も **空の `lists`** にフォールバック。

### 8.4 保存失敗

- 保存エラー時はコンソールに警告を出すが、アプリは継続動作を試みる。

## 9. ID 生成

- `crypto.randomUUID()` が利用可能な場合はそれを使用。
- 利用できない環境では、時刻とランダム文字列を組み合わせた **一意性の高い文字列** にフォールバックする。

## 10. UI 文言（日本語）

主要な UI 表記の例:

- 完了 / スキップ / タスク追加 / 保存 / キャンセル  
- リスト・タスクの **名前変更・編集** は **鉛筆アイコン**（意味は `aria-label` で示す）  
- リスト・タスクの **削除** は **ゴミ箱アイコン**（意味は `aria-label` で示す）  
- **最終完了日** は **時計アイコン** ＋ 月/日（曜）（`aria-label` で「最終完了 …」を補う）  
- リストを作成  
- 最初のタスクを追加しましょう  
- このあと  
- すべてのデータを削除  

トーンは **責めない・シンプル** な日本語を用いる。

## 11. ビルド・デプロイ（参考）

- 本番は `npm run build` により `dist/` を生成する。
- `vite.config.js` の `base` は **相対パス**（`./`）とし、静的ホスティングでの読み込みを安定させる。
- ビルドは **単一の `index.html` にインライン化**され、`file://` で開くことも可能。環境によっては **`npm run preview`** や本番 URL での確認が確実。
- GitHub Actions 等による FTP デプロイは **別途インフラ・Secrets 設定** に依存する（本仕様の必須要件ではない）。
