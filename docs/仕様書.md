## 1. 製品概要

### 1.1 位置づけ

本製品は **汎用タスク管理ツールではない**。ユーザーが **順番に一つずつ** 作業し、**完了した項目をリスト末尾へ回す** **シーケンシャルループ（循環キュー）** を支援する Web アプリである。

- 締切・優先度・評価を設けず、判断負荷を減らす。  
- 各リスト内では **配列の先頭＝いまやる1件**、完了で末尾へ回す。

### 1.2 名称

- **表示名**: じゅんぐりタスク  
- `document.title` および画面見出しに使用。

### 1.3 技術スタック（再現時の前提）

| 区分 | 技術・備考 |
|------|------------|
| 言語 | JavaScript（ES モジュール） |
| UI | React 18（関数コンポーネント + Hooks） |
| ビルド | Vite 5 系 |
| スタイル | Tailwind CSS 3 系、PostCSS + Autoprefixer |
| 永続化 | ブラウザ `localStorage` のみ。**バックエンド・DB なし** |

### 1.4 動作環境

- **モバイルファースト** のレイアウト。  
- `localStorage` と **ES modules**（`type="module"`）に対応したモダンブラウザ。  
- 本番は **HTTPS または localhost** でモジュール読み込み可能なホスト上に静的ファイルを配置する想定。

## 2. 用語

| 用語 | 意味 |
|------|------|
| リスト | タスクの集合。最大 3 件まで。他リストとデータ共有しない。 |
| 先頭タスク | `tasks[0]`。UI では「次にやる」大きなカード。 |
| 完了 | 先頭タスクに対し `lastCompletedAt` を更新し、複数件時は末尾へ移動。 |
| スキップ | 先頭を末尾へ移動するが `lastCompletedAt` は変更しない（2件以上時のみ）。 |
| 最終完了日時 | `lastCompletedAt` が指す時刻を、UI 上で日付＋時刻（短形式）で示したもの。 |
| このあとの並べ替え | `tasks[1]` 以降の順序を **上向き／下向き矢印ボタン** で1段ずつ入れ替える操作。先頭 `tasks[0]` とは入れ替えない。 |

- `useLocalStorage()` が `{ lists }` を `junguri-task-data` キーで読み書き。

- `setData` は React の `setState` 相当（関数型更新可）。  
- `TaskScreen` / `ListSelection` は `setData` でイミュータブルに `lists` を更新する。

- **React Router 等は使わない**。単一ページ内の条件レンダリングのみ。

## 5. 画面1：リスト選択（詳細）

### 5.1 レイアウト要素（上から）

1. 見出しテキスト「じゅんぐりタスク」（`text-xl font-light` 系の軽いトーン）。  
2. 登録済みリスト：各 **白カード** 内に  
   - 左：リスト名（タップで画面2へ）。  
   - 右：**鉛筆**（名前を変更）、**ゴミ箱**（削除）。  
3. リスト件数 `< 3` のとき：**破線枠**エリアに「リスト名を入力」プレースホルダ、`リストを作成` ボタン。  
4. 画面下部：`すべてのデータを削除`（テキストリンク風）。

### 5.2 リスト名のインライン編集

- 鉛筆タップで同一カードが **入力欄 + 保存 + キャンセル** に切り替わる。  
- Enter キーで保存可。  
- 保存時：名前を `trim`。**空なら変更前の名前を維持**。  
- キャンセル：編集状態を閉じ、入力は破棄。

### 5.3 リスト作成

- `trim` した入力が空なら名前は **「新しいリスト」**。  
- 既に 3 件ある場合は **作成処理を実行しない**（UI も作成エリアを出さない）。

### 5.4 リスト削除

- ゴミ箱タップで **確認なし** で即削除（現行実装）。該当リストを `lists` から除去。

### 5.5 すべてのデータを削除

- タップで **モーダル**表示。  
- 文言例：「すべてのリストとタスクが削除されます。よろしいですか？」  
- `キャンセル` / `削除する`。確定で `lists` を空配列に戻す。

### 5.6 定数

- `MAX_LISTS = 3`（コード上の定数と一致させる）。

## 6. 画面2：タスク画面（詳細）

### 6.1 ヘッダ

- 左：**戻る**（←、`aria-label="戻る"`）。  
- 中央：リスト名（長い場合は `truncate`）。  
  - リスト名タップ **または** 右の **鉛筆** でインライン編集。  
  - 編集時：入力欄、保存、キャンセル、Enter で保存。  
  - 空保存 → **変更前の名前維持**。  
- 別リストを開いたときヘッダ編集状態はリセットする（`list.id` 変化で `useEffect`）。

### 6.2 タスク 0 件

- 中央寄せメッセージ：「最初のタスクを追加しましょう」。  
- タスク名入力、`タスク追加`。Enter で追加可。  
- **空 trim の追加は不可**（ボタン・Enter いずれも無効化相当）。

### 6.3 タスク 1 件以上：先頭カード（大）

- 白背景・角丸大・影ありの **カード**。  
- **通常時**  
  - 1 行目：タスク名（タップで編集モード）＋ 右端 **⋮**（`aria-label="その他"`）。  
  - 2 行目：**最終完了行**（条件付き、後述 §10）。  
  - ⋮ 展開時：名前を編集（鉛筆）、タスクを削除（ゴミ箱）。展開は ⋮ のトグル。  
  - **完了**（主ボタン・濃色）、条件付き **スキップ**（枠線ボタン）。  
- **編集時**  
  - 入力欄、保存、キャンセル、Enter で保存。  
  - 編集中は **完了・スキップ・最終完了行を出さない**（編集 UI のみ）。

### 6.4 タスク 1 件以上：「このあと」

- 見出し行：**左**に「このあと」（小さめ・薄色）、**右端**に **並べ替え矢印の表示トグル**（`ReorderArrowsBadge`：上下矢印を縦に並べたアイコン。ON で濃色、OFF で薄色）。`aria-pressed` と `aria-label`（「並べ替え矢印を表示する」／「並べ替え矢印を隠す」）。**デフォルト ON**。選択は `localStorage` に保存（§9.1）。  
- **トグル OFF** のとき：各行の **左列の矢印ボタンは出さない**。並べ替え操作はできないが、**タスクの順序データは変えない**。  
- 各タスク **行カード**（左から右へ）：  
  - **左列**（表示トグル ON のときのみ）：**上向き矢印**・**下向き矢印** の縦並びボタン（§7.6）。表示はアイコンのみ、意味は `aria-label`（`順番を上へ`／`順番を下へ`）。  
    - **上向き**：`tasks[1]` の行では **無効**（先頭タスクと入れ替えない）。それ以外の「このあと」では、直前のタスクと入れ替え。  
    - **下向き**：末尾の「このあと」では **無効**。それ以外では直後のタスクと入れ替え。  
  - **右エリア**：  
    - 1 行目：タスク名（タップで編集）＋ 鉛筆 ＋ ゴミ箱。  
    - 2 行目：**最終完了行**（条件付き）。  
- **編集時** は入力 + キャンセル/保存のみ（**矢印ボタン・最終完了行は出さない**）。  
- **削除** はゴミ箱 → モーダル「このタスクを削除しますか？」→ キャンセル / 削除する。

### 6.5 タスク追加（1件以上時）

- 画面下部、区切り線の下。  
- プレースホルダ「新しいタスク」、ボタン「タスク追加」。  
- **常に配列末尾** に追加。空 trim は追加しない。

### 6.6 スキップボタン表示条件

- **タスクが 2 件以上** のときのみ表示。1 件のみでは **非表示** かつ処理もしない。

## 7. タスク操作アルゴリズム

配列 `tasks` の **インデックス 0 が先頭**。以下 `head = tasks[0]`、`tail = tasks.slice(1)` とする。

### 7.1 完了（`handleComplete`）

1. タスクが 0 件なら何もしない。  
2. **1 件のみ**  
   - 順序は変えない。  
   - `head.id` に一致するタスクの `lastCompletedAt` を `Date.now()`（ミリ秒）に更新。  
3. **2 件以上**  
   - `head` を配列から外す。  
   - `head` の `lastCompletedAt` を `Date.now()` に更新したオブジェクトを **末尾** に追加。  
   - 結果：`tasks = [...tail, updatedHead]`。

### 7.2 スキップ（`handleSkip`）

1. 1 件以下なら何もしない。  
2. `tasks = [...tail, head]`（`head` のフィールドはそのまま。**`lastCompletedAt` は変更しない**）。

### 7.3 削除

- `tasks` から該当 `id` を除去。先頭削除時は自動的に次が先頭になる。

### 7.4 追加

- `{ id: 新規ID, name: trim済み文字列, lastCompletedAt: null }` を **末尾** に追加。

### 7.5 名前の編集

- 該当タスクの `name` のみ更新。`trim` 後空なら **従来の name を維持**。  
- `id`・`lastCompletedAt`・順序は不変。

### 7.6 「このあと」の順番変更（矢印ボタン）

- **表示トグルが ON** のときのみ、各行の矢印ボタンから操作可能。OFF のときは UI 上、並べ替え不可。  
- 対象は **`tasks[1]`〜`tasks[n-1]`** のみ。`tasks[0]`（先頭カード）は **この操作では動かさない**。  
- **上向き矢印**：インデックス `i` のタスクについて、`i >= 2` のときのみ有効。`tasks[i]` と `tasks[i-1]` を **入れ替え**（`i === 1` では無効＝先頭と入れ替えない）。  
- **下向き矢印**：インデックス `i` について、`1 <= i < n-1` のときのみ有効。`tasks[i]` と `tasks[i+1]` を **入れ替え**。  
- 各タスクオブジェクトの **`id`・`name`・`lastCompletedAt` はそのまま**（参照の入れ替えのみ）。  
- **ドラッグ＆ドロップは用いない**（マウス・キーボードで同等に操作可能なボタン方式）。

## 9. データモデルと永続化

### 9.1 localStorage

| 項目 | 値 |
|------|-----|
| キー（タスクデータ） | `junguri-task-data` |
| 値 | `JSON.stringify(data)`、`data = { lists: List[] }` |
| キー（UI） | `junguri-task-show-reorder-arrows` |
| 値 | `'true'` または `'false'`。**未設定時は「表示」とみなす**（デフォルト ON）。リストデータとは独立。 |

### 9.2 List（論理型）

```ts
type List = {
  id: string
  name: string
  tasks: Task[]
}
```

### 9.3 Task（論理型）

```ts
type Task = {
  id: string
  name: string
  lastCompletedAt: number | null  // Unix エポックミリ秒。未完了は null
}
```

### 9.4 読み込み時の検証（現行）

- `JSON.parse` 失敗 → `{ lists: [] }`。  
- ルートがオブジェクトでない、`lists` が配列でない → `{ lists: [] }`。  
- **タスク各フィールドの深いバリデーションは行わない**（欠損があってもそのまま動作に任せる実装）。再現時は同様または強化を選択可。

### 9.5 保存失敗

- `try/catch` で `console.warn`、アプリは継続を試みる。

## 10. 最終完了日時の表示仕様

### 10.1 表示条件

- `lastCompletedAt == null` のとき **行自体を表示しない**。  
- 編集モード中（タスク名編集 UI 表示中）も **表示しない**。  
- 値は `Number(lastCompletedAt)` が有限なら使用。非有限・不正日付なら行を出さない。

### 10.2 書式（日本語・ローカル TZ）

- 端末の **ローカルタイムゾーン** で `Date` に変換。  
- **年は表示しない**。  
- **秒は表示しない**。  
- 形式（正規表現イメージ）:  
  `{月}/{日}（{曜1文字}） {HH}:{MM}`  
  - 月・日：数値（先頭ゼロなし可、実装ではそのまま出力）。  
  - 曜：`日` `月` `火` `水` `木` `金` `土`（`getDay()` 0=日）。  
  - `HH`・`MM`：**2桁ゼロ埋め**、**24時間制**。  
- 例: `4/5（日） 14:30`、`12/3（水） 09:05`  
- 日付と時刻の間は **半角スペース 1 つ**。

### 10.3 意味

- **`lastCompletedAt` が指す瞬間**のローカル日時。キュー上の位置とは無関係。  
- スキップ後も、過去に完了していれば **表示は残る**（値が変わらないため）。

### 10.4 UI 構造

- **時計アイコン**（左）＋ テキスト。  
- セマンティック：外側 `role="status"`、`aria-label` に「最終完了 {全文}」。  
- 内側は `time` 要素、`dateTime` 属性に **ISO 8601**（`toISOString()`）を入れてよい。  
- 先頭カード：**タスク名の直下**、⋮ メニューより上。完了/スキップボタンより上。  
- 「このあと」行：**1 行目（名前・アクション）の直下**。  
- レイアウト：`flex-wrap`・`w-full`・`min-w-0` 等で折り返し可能にし、狭い幅でも欠けにくくする。  
- **完了直後のトーストは付けない**。日時専用の詳細メニューも **付けない**。

## 15. ビルドと成果物

### 15.1 コマンド

| コマンド | 用途 |
|----------|------|
| `npm run dev` | 開発サーバ |
| `npm run build` | `dist/` 生成 |
| `npm run preview` | `dist` のローカル確認（`file://` 直開きはモジュール制約で非推奨） |

### 15.2 Vite 設定（再現の要点）

- `base: './'`：**相対パス**。サブディレクトリ配信や静的ホストでパスがずれにくい。  
- **単一 HTML に JS をインライン化しない**（CSP でブロックされうる）。通常の chunk 出力。  
- `build.assetsDir: ''`：**成果物をフラット**にする（`dist/index.html` と同階層に `index-[hash].js` / `index-[hash].css`）。**FTP でサブフォルダ作成に失敗する環境**向け。

### 15.3 本番 `dist` の内容

- `index.html`  
- `index-*.js`（エントリバンドル）  
- `index-*.css`  
- **いずれもアップロード必須**。`index.html` のみでは動かない。

## 16. デプロイ時の注意

- ビルドのたびに **ハッシュ付きファイル名** が変わる。**`index.html` と新しい `.js` / `.css` を同じデプロイで揃える**こと。  
- ブラウザ・CDN の **キャッシュ**で古い JS が残ると、見た目が更新されない。**強制再読み込み**で確認。  
- GitHub Actions + FTP 等を使う場合、Secrets（例: `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`, 任意 `FTP_SERVER_DIR`, `FTP_PROTOCOL`）の扱いはインフラ依存。

## 17. スコープ外

- 締切・リマインダー・カレンダー連携  
- 優先度・タグ・メモ・添付  
- **ドラッグ＆ドロップ** による並べ替え（**「このあと」の矢印ボタンによる並べ替えは実装する**）
